# HeadStart website journey — placement research and decisions

Research date: **2 October 2026**. Primary sources below were opened and read in this session. Scope: Home, global navigation, Search, Hiring now, Trends, Saved searches, Saved jobs, Profile, Résumé, onboarding, feedback and motion. Initial repository observations used `48ff7c14`; the redesign was then integrated with main `10e45e04`, including public browsing and the new Trends coverage panels. These are local changes, not a deployed release.

The intended journey is: understand the offering → find relevant jobs → inspect the employer's listing → save useful jobs/searches → return or prepare a résumé → apply with the employer. Marketing succeeds when this useful path is easy to discover and credible. **No conversion, retention or user-preference improvement has been measured for HeadStart.** Every expected marketing benefit below is a hypothesis, not a promised uplift.

## What the evidence actually supports

Evidence labels: **E** = the source's own empirical usability research; **G** = first-party design guidance; **N** = accessibility criterion, explained by its issuing standards body; **H** = our application to HeadStart. E does not mean an experiment on HeadStart, G is not a preference poll, and N is not a conversion study.

- **Visible navigation has a discoverability advantage.** NN/G's study used 179 participants and six sites; hidden navigation performed worse than visible/combination navigation. Its mobile comparison tested hidden versus combination, **not** all-visible navigation. This supports exposing important destinations and providing in-page links to others, not claiming that bottom navigation beats top navigation. [NN/G navigation study][s1]
- **Promote useful filters, particularly on mobile.** Baymard observed people narrowing product/travel lists through prominent filters. It recommends retaining promoted filters in the complete filtering interface too. Selecting Country, Remote and experience for HeadStart is H: their relative importance is not established by those studies. [Baymard promoted filters][s3]
- **Show the applied filters, not only their number.** Baymard's tests found that missing overviews caused disorientation, confirmation work and slower removal. An overview above results with individually removable values is justified; several desktop positions worked and testing did not identify one universal winner. Avoid hiding overflowing selected values without a clear indication. [Baymard applied filters][s4]
- **Help at the moment of action.** NN/G finds that walkthroughs are often skipped and poorly remembered; contextual, revisitable help is usually more appropriate. A voluntary tour is reasonable, but requiring it before searching is not. [NN/G onboarding][s8]
- **Make the next action legible.** GOV.UK recommends action-describing labels, visual priority for the main action, sparing warning styling and confirmation for serious destructive actions. These are design-system recommendations, not proof of a particular HeadStart button color or position. [GOV.UK buttons][s5]
- **Appearance has constraints, not magic numbers.** WCAG addresses target size, contrast, focus and motion; it does not prescribe a selling color or corner radius. A 44px touch target is our comfortable implementation choice; WCAG 2.2 AA SC 2.5.8 uses 24×24 CSS pixels with stated exceptions. Interaction-motion suppression is SC 2.3.3 **AAA**. [Target size][s10], [motion][s13]

## Corrections and unresolved choices

1. **Do not collapse all phone filters.** The first redesign draft did this. The revised draft promotes the actual Country/experience/remote fields outside the advanced disclosure. This follows the promoted-filter evidence without cloning state or inventing measured seeker preferences. Other common constraints should be promoted if task research reveals the need. [Promoted filters][s3]
2. **Bottom navigation is an implementation hypothesis.** The sources justify exposing important links, not its exact location or the current decision to expose Résumé rather than Saved searches. Test both against real returning-seeker tasks. Fixed bars require reserved space and scroll treatment so focused controls are not covered. [Mobile patterns][s2], [Focus not obscured][s12]
3. **Accessible names do not solve sighted icon ambiguity.** A star's `aria-label` supports assistive technology, but does not teach a sighted phone visitor whether it means rating or saving. The implementation now uses visible Save/Saved text, preserving the accessible labels and pressed state. [Icon usability][s15]
4. **CSS reordering is not automatically a WCAG failure.** Focus order must preserve meaning and operation; exact visual order is best practice, not the sole permitted order. Putting chart-question controls below the chart still requires a deliberate coherence check. [Focus order][s11]
5. **No universal selling shape/color was established.** Keep radius, color, surfaces and shadow in the replaceable skin; dimensions, spacing, text metrics and responsive order in layout. Font or border-width changes can change geometry and need layout review. The seam is useful only if an actual replacement skin preserves measured placement.
6. **Truth is part of the offer.** Keep the employer-source distinction, language/role scope and dated measurement limits. A fixture preview is not live proof; similarity is not suitability; source links are not a guarantee of a job still being open. These are product-contract decisions, not claims extracted from a marketing study.

## How to validate selling impact

First compare unprompted task completion, first-action comprehension, time to an inspected employer listing, accidental actions, feature discovery and recovery. Include first-time and returning seekers, phones and desktop, keyboard navigation, enlarged text and reduced motion. Small usability sessions reveal failure modes; they do not establish percentage conversion lift.

If an authorised product experiment is later run, predefine the useful event and denominator: first relevant source inspection per eligible visit; successful shortlist/search retention; return to saved work; successful résumé export. Do not equate raw clicks, mandatory sign-ins or tour completion with customer success. Compare variants under the same access/data conditions and keep account-policy work separate from placement attribution. Privacy-preserving aggregate measurement and experiment implementation are outside this research change.
